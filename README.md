# UltraCopy for Ubuntu Ver.0.7.9

Ubuntu向けのGUIファイルコピー試作アプリです。

## 主な機能
- ファイル・フォルダーのコピー
- `copy_file_range`を優先し、利用できない場合は通常コピーへ切替
- コピー後のSHA-256検証（初期設定で有効）。コピー先はメモリ上のキャッシュではなく、ディスクから読み直して照合する（O_DIRECT）
- コピー進捗・速度・残り時間の表示
- 一時停止・再開・中止
- SQLiteによるコピー履歴
- 同名項目を上書きしない
- スパースファイル（仮想マシンのディスクイメージなど）は穴を保ったままコピー
- コピー前に空き容量を確認し、明らかに足りない場合は開始しない
- ファイル・フォルダー・公開（rename）の結果をディスクに確定（fsync）してから完了とし、停電直後でも公開済みのコピーが消えにくいようにしている
- コピー全体をコピー先と同じファイルシステム上の一時領域に作成し、完了後に公開
- 中止・エラー時は一時コピー領域を自動清掃（読み取り専用フォルダーを含む場合も清掃）
- コピーできない特殊ファイル（FIFO・ソケット・デバイス）はスキップし、件数と一覧を完了メッセージとコピー履歴に表示
- コピー中にウィンドウを閉じた場合は、中止と清掃を終えてから終了
- 強制終了などで残った一時コピー領域を、次回コピー時に検出して削除を提案

## 動作環境
- Ubuntu（Linux）
- Python 3.10 以上（Ubuntu 22.04 標準の Python 3.10 で動作します）
- python3-venv（`sudo apt install python3-venv`）

## インストール（DEB パッケージ・おすすめ）
Ubuntu 25.04 以降（26.04 LTS を含む）では、DEB パッケージでインストールできます。

1. [Releases](https://github.com/kenjiiida-commits/UltraCopy/releases) から `ultracopy_<バージョン>_all.deb` をダウンロードします。
2. ダウンロードしたフォルダーで端末を開き、次を実行します（PySide6 も自動でインストールされます）。

```bash
sudo apt install ./ultracopy_0.7.9_all.deb
```

インストール後は、アプリ一覧の「UltraCopy」から起動できます。端末から `ultracopy` と入力しても起動します。

アンインストール:

```bash
sudo apt remove ultracopy
```

Ubuntu 22.04・24.04 には PySide6 の公式パッケージがないため、DEB は使えません。次の「起動方法（ソースから）」で起動してください。

## 起動方法（ソースから）
端末でこのフォルダーへ移動し、次を実行してください。

```bash
chmod +x 起動.sh
./起動.sh
```

初回起動時に仮想環境を作成し、PySide6をインストールします。
インターネット接続が必要です。

## 注意
- 開発中の試作品です。重要データの唯一のバックアップ用途には使用しないでください。
- 実運用前に、必ずテスト用フォルダーとダミーファイルで動作確認してください。
- コピー元の所有者・ACL・拡張属性など、すべてのメタデータを完全に複製するものではありません。
- 一時領域はコピー先フォルダー内に `.ultracopy-staging-` で始まる隠しフォルダーとして作成されます。コピー中はその分の空き容量が必要です。
- コピー先に同名項目がある場合は上書きしません。

## 試験の実行方法
`./起動.sh` を一度実行して仮想環境を作ったあと、一般ユーザーで次を実行します。

```bash
bash tests/run_all_tests.sh
```

最後に「合計: PASS … / FAIL 0」と表示されれば、すべての試験に合格しています。
ループデバイスを使う一部の試験（ディスク上だけ壊れたデータを検証で検出できるか）は、root で実行したときだけ動きます。

## DEB パッケージの作り方
UltraCopy のフォルダーで次を実行すると、`dist/` に DEB ファイルができます。バージョンは `src/main.py` の `APP_VERSION` から決まります。

```bash
bash packaging/build_deb.sh
```

## 確認済みの範囲
- 自動試験（約 600 項目）: Ubuntu 系の Linux（カーネル 6.x、ext4・tmpfs）で、Python 3.10 / 3.13 / 3.14、一般ユーザーと root の両方で合格
- DEB パッケージ: Ubuntu 26.04 LTS で、インストール・起動・アンインストールと、Ubuntu の PySide6 パッケージでの動作を確認
- 実機の USB メモリ（FAT 系）へのファイル・フォルダーのコピーと検証を確認
- 停電は再現できないため、ディスクへの書き込み確定（fsync・syncfs）は、呼び出しの順序を記録する方法で確認しています
- 次の環境は、試験で動作を模擬したのみで、実機では確認していません
  - NTFS の USB メモリ、ネットワークドライブ（NFS・SMB）、FUSE
  - ARM（Raspberry Pi など）
  - Btrfs・XFS・ZFS

不具合を見つけた場合は Issue でお知らせください。

## 変更履歴
### Ver.0.7.9
- DEB パッケージに対応（Ubuntu 25.04 以降）。アプリ一覧への登録、アイコン、`ultracopy` コマンド、説明書（`man ultracopy`）を追加
- DEB の作成用スクリプト `packaging/build_deb.sh` を追加

### Ver.0.7.8
- 非常に深いフォルダー階層をコピーできるように変更。これまでは次の3つの理由で失敗していた
  - Python の再帰の上限（約 1000 階層で RecursionError）→ 再帰を使わない処理に変更
  - コピー先のパスの長さの上限 4096 バイト（長い日本語の名前なら 40 階層程度で File name too long）→ コピー先もフォルダーの FD を基準に作るように変更
  - 階層の数だけフォルダーを開いたままにしていた（一般ユーザーの上限は通常 1024）→ 同時に開くフォルダーを常に一定数に
- 一時コピー領域の清掃・残った一時コピー領域の削除・容量の見積もりも、深い階層に対応
- コピー中に途中のフォルダーが別の場所へ移動された場合は、検出して停止する

### Ver.0.7.7
- 上書き防止付きの移動（RENAME_NOREPLACE）に対応していないファイルシステムでも公開できるように変更。ファイルはハードリンク方式、フォルダー（とハードリンク不可のファイル）は名前を予約する方式で、既存の項目を上書きしない
- renameat2 のシステムコール番号を CPU ごとの表に変更（ARM・Raspberry Pi・RISC-V など。64ビットカーネル上の 32ビット版にも対応）。分からない CPU では呼び出さない
- Linux 5.8 以降では、ファイル・フォルダーごとの fsync をやめ、公開前に syncfs で一括確定するように変更（小さいファイルが多いコピーが速くなった）
- スパースファイルの穴を保ったままコピーするように変更（見かけ 2 GiB・実データ 16 MiB のイメージが、コピー先で 2 GiB を使っていた）
- 進捗表示の更新を 0.1 秒間隔に制限（高速なSSDで画面の更新が追いつかなくなるのを防ぐ）
- 通常コピーの経路で、読み込み用のバッファを使い回すように変更
- コピー前に空き容量を確認（スパースファイルやハードリンクで多く見積もりすぎないように計算）
- Ver.0.7.6 で、小さいファイルを検証付きでコピーすると約3倍遅くなっていた問題を修正（1ファイルを2回読んでいた、作業用バッファを毎回作っていた）

### Ver.0.7.6
- SHA-256検証で、コピー先をページキャッシュではなくディスクから読み直すように変更（O_DIRECT）。これまでは、ディスク上のデータが壊れていても、メモリ上のキャッシュが正しければ「検証済み」になる可能性があった
- O_DIRECT 非対応のファイルシステムでは、キャッシュを捨てたことを確認（mincore）してから読む。確認できない場合は検証結果を「SHA-256検証済み（一部キャッシュ経由の可能性あり）」と表示
- 所有者に読み取り権限がない権限（例: 0204）のファイルを一般ユーザーでコピーすると、検証で失敗していた問題を修正（Ver.0.7 からの問題）

### Ver.0.7.5
- コピーしたフォルダーと、公開先の親フォルダーもディスクに確定（fsync）するように変更。停電直後に、公開したはずのコピーが消えたり一部のファイルが見えなくなったりすることへの対策
- ファイルの確定（fsync）を、日時・権限の設定の後に行うように変更（属性も含めて確定させるため。回数は従来どおり1ファイル1回）
- fsync に対応していないファイルシステムでは警告を出し、完了メッセージに「一部未確定」と表示
- 公開後の確定に失敗した場合は、「公開済みだが確定に失敗」と分かるエラーにした

### Ver.0.7.4
- スキップした特殊ファイル（FIFO・ソケット・デバイス）の件数・種類・パスを、完了メッセージとコピー履歴に表示するように変更（これまではログに出るだけで「成功」と表示されていた）
- スキップがあった場合の結果を「成功（スキップあり）」とし、履歴の絞り込みに追加。完了メッセージも注意アイコンで表示
- エラー・中止で止まった場合も、それまでにスキップした項目を履歴に記録

### Ver.0.7.3
- フォルダー内の項目を名前順に処理するように変更（ファイルシステムによって処理順・ログ・ハードリンクの代表ファイルが変わらないようにした）
- 試験 test_hardlink_source_mutation_after_hash.py が処理順に依存して失敗する問題を修正
- 試験 test_hardlink_source_replacement_before_publish.py の名前順走査の代用品が Python 3.13 で動かない問題を修正

### Ver.0.7.2
- コピー元のフォルダーを、パスではなく開いたフォルダー（FD）を基準にたどるように変更。コピー中に途中のフォルダーがシンボリックリンクや別のフォルダーに差し替えられても、コピー元の外のファイルを読まないようにした（TOCTOU対策）
- コピー元の通常ファイルが FIFO に差し替えられると、処理が止まったままになる問題を修正
- フォルダーの日時・権限・拡張属性を、コピー時に開いたフォルダーから読み取るように変更

### Ver.0.7.1
- ハードリンクを作れないドライブ（FAT/exFAT など）で、ファイルの日時・権限が失われ、検証前のデータで公開されていた問題を修正
- 読み取り専用フォルダーを含むコピーが失敗・中止したとき、一時コピー領域が残る問題を修正
- 読み取り専用のフォルダーそのものをコピーすると、公開時に失敗する問題を修正
- コピー中にウィンドウを閉じたとき、清掃せずに異常終了する問題を修正
- 強制終了などで残った一時コピー領域を検出・削除する機能を追加
- Python 3.10 で清掃処理がエラーになる問題を修正（Python 3.11 専用機能を使わないように変更）
